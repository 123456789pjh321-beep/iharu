# UI134 — 월 예산·소비 통계와 공통 전체선택

기준: 운영 UI133 `d35deb45605de744a6c74c58b6b5185e67e9649d`.

## 벤치마킹과 적용

네이버 가계부 공식 고객센터의 예산 작성·수정, 분류·결제수단별 통계, 수입·지출 흐름, 자주 쓰는 내역 안내를 검토했습니다. 로그인한 네이버 계정의 실제 화면이나 개인 자료에는 접근하지 않았습니다.
출처: https://help.pay.naver.com/faq/list.help?categoryId=10502 (2026-11-10 확인).

| 참고한 흐름 | 아이하루 적용 |
| --- | --- |
| 수입·지출 입력 | 익숙한 수입·지출 용어와 받은 돈·쓴 돈 설명, 분류·결제 방법 직접 입력 |
| 예산 작성·수정 | 나의 월 예산 설정·수정·해제, 예정 지출을 포함한 남은 예산 |
| 통계·수입/지출 흐름 | 분류·결제방법별 지출, 최근 3개월 수입·지출, 지난달 비교 |
| 자주 쓰는 내역 | 최근 내역의 내용·분류·결제 방법을 복사하는 빠른 입력 |
| 한 달 보기 | 달력·날짜별 내역·통계 보기 전환 |

은행·카드 자동 연동은 추가하지 않았습니다. 가계부는 사용자가 입력한 기록을 기준으로 계산합니다.

## 사용 방법과 합계 기준

- 요약은 완료한 지출·수입과 예정 지출을 구분합니다. 수입을 입력하지 않아도 부족금이나 채무로 해석하지 않습니다.
- 구성원 필터와 조회 월은 월 요약·예산·통계에 공통 적용됩니다. 내용 검색과 수입·지출 선택은 달력·내역에 적용됩니다.
- 통계는 기본으로 완료한 내역을 보여줍니다. 예정 포함을 켜면 완료·예정 내역을 모두 합산합니다. 분류·결제 방법 통계는 지출만 집계합니다.
- 최근 3개월은 조회 월과 앞의 두 달입니다. 같은 구성원과 완료·예정 조건으로 비교합니다.
- 월 예산은 내 계정, 조회 월, 선택한 구성원 조합별로 저장합니다. 같은 그룹의 다른 계정 예산과 공유되지 않습니다. 선택 순서는 예산 구분에 영향을 주지 않습니다.
- 예산 사용 금액은 완료·예정 지출 합계입니다. 예정 지출임을 표시하고 예산 초과도 양수 금액으로 안내합니다.
- 최근 내역으로 입력은 저장 전 편집 초안입니다. 선택 월의 오늘 또는 1일을 기본 날짜로 사용하고 한 번 등록·미완료로 시작하므로 반복 내역이 의도치 않게 중복되지 않습니다. 내용·금액·분류·담당자 등을 확인한 뒤 저장하세요.
- 전체선택은 시간표·달력·가계부·홈의 공통 구성원 필터에 적용됩니다. 좁은 화면에서는 +N명 창 안에서도 전체선택할 수 있습니다. 하나씩 해제할 수 있으며 최소 한 명은 남깁니다. 선택을 다음 접속에도 유지하려면 첫 화면으로 저장을 누르세요.
- CSV 저장 버튼과 이전에 삭제한 세 안내 문구는 표시하지 않습니다. 기존 반복 기록·완료 상태·그룹 공유·작성자/담당자 권한은 유지합니다.

## 데이터베이스와 적용 순서

- 추가 마이그레이션: `20261110022018_workspace_ledger_budgets.sql`.
- `db/migrations`가 앱 마이그레이션 실행 기준이며 `supabase/migrations`는 동일 내용의 미러입니다. 두 경로의 SQL을 같은 DB에 각각 수동 실행하지 마세요.
- 기존 배포 환경에서는 앱의 마이그레이션 실행 방식(`npm run db:migrate`)을 사용해 DB를 먼저 적용하고 서버·클라이언트를 함께 배포합니다. 설정값이나 인증 정보는 ZIP에 포함하지 않습니다.
- 운영 DB에는 해당 마이그레이션과 정확한 체크섬을 등록했습니다. 같은 체크섬은 다시 실행하지 않습니다.
- 새 개인 예산 테이블은 강제 RLS를 사용합니다. 실행 계정의 직접 테이블 접근과 이전 명령 함수 실행은 차단합니다. 현재 명령 함수에서 세션·일반사용자 권한·현재 읽을 수 있는 구성원을 검증합니다.
- 저장 버전으로 동시 수정 충돌을 확인합니다. 충돌 시 최신 버전을 읽고 입력값을 남겨 재확인할 수 있습니다. 0원 해제도 버전을 보존합니다.
- 이전 앱으로 되돌릴 때 새 테이블·함수는 남겨도 기존 동작과 호환됩니다. 적용된 마이그레이션 파일은 수정하거나 삭제하지 마세요.
