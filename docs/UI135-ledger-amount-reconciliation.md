# UI135 — 지출·수입·잔액과 날짜별 금액 일치

기준: 운영 UI134 `103bc242e52c823a05a70019d02182b4e1758c56`.

## 적용 결과

- 상단을 지출·수입·잔액으로 구성합니다. 잔액은 조회한 수입에서 지출을 뺀 금액입니다.
- 완료·예정 구분을 제거합니다. 과거·오늘·미래 여부와 이전 상태에 관계없이 해당 날짜에 등록된 금액을 모두 합산합니다.
- 입력창의 완료 체크, 내역의 상태 변경 버튼, 달력의 완료/예정 표시, 통계의 예정 포함 체크를 제거합니다.
- 조회 월·구성원·수입/지출·검색 조건을 요약·달력·날짜 상세·내역·통계에 동일하게 적용합니다. 통계의 최근 3개월도 같은 조건으로 계산합니다.
- 월 예산은 선택한 구성원의 해당 월 전체 지출과 비교합니다. 검색이나 수입/지출 선택에 따라 월 예산 사용 금액이 줄어들지 않습니다. 안내를 ‘이번 달 지출 기준’으로 바꿉니다.
- 기존 내역·반복 날짜·금액·작성자·공유 권한·전체선택·예산 저장은 유지합니다. DB 마이그레이션은 없습니다.
- 이전 저장 형식의 상태 필드는 호환성을 위해 보존하지만 현재 화면과 가계부 계산에서는 사용하지 않습니다. 기존 내역을 다시 저장하거나 상태를 일괄 변경할 필요가 없습니다.
- CSV 버튼은 계속 표시하지 않습니다. 내부 CSV 변환 함수에서도 상태 열을 제거합니다.

## 제보 화면 금액 확인

| 항목 | 금액 |
| --- | ---: |
| 11월 1일 지출 | 1,168,000원 |
| 11월 23일 지출 | 284,000원 |
| 11월 지출 | 1,452,000원 |
| 11월 수입 | 0원 |
| 11월 잔액 | -1,452,000원 |

종전에는 날짜 칸은 모든 내역을 합산하고 상단은 완료 처리된 444,000원만 보여주어 기준이 달랐습니다. 이번 패치는 완료·예정 기준 자체를 제거하므로 1일의 1,168,000원도 월 지출에 전액 반영됩니다. 사용자 거래 데이터는 수정하지 않았습니다.

검증용 7개 내역으로 두 날짜의 합계를 재현했습니다. 각 개별 거래의 금액·내용은 제보 사진에 없으므로 테스트 데이터는 같은 합계를 만드는 가상 내역이며 실제 사용자 내역을 복사한 것이 아닙니다.

## 검증

- 검증 소스: `398a37aa880cb6e246bac08b1e1a90ff365aad7e`.
- GitHub Actions Household ledger [42749310535](https://github.com/123456789pjh321-beep/iharu/actions/runs/42749310535): 단위·API 271개, 타입 검사·운영 빌드, 브라우저 34개 모두 통과.
- 7개 내역의 이전 저장 상태를 섞어도 1일 1,168,000원, 23일 284,000원, 월 지출 1,452,000원, 수입 0원, 잔액 -1,452,000원으로 일치합니다.
- 입력·달력·날짜 상세·내역·통계에 상태 조작과 예정 문구가 없음을 확인했습니다. 이전 상태 값을 뒤집어도 금액이 달라지지 않는 단위 테스트를 포함합니다.
- 조회 월·검색·수입/지출 변경, 구성원 필터, 통계·결제 방법·최근 3개월 합계, 예산 저장, 최근 내역 복사, 비회원 로그인, 반복 기록·모바일 터치를 검증했습니다.
- 320·390·820·1440px 화면에서 가로 넘침 없이 표시됩니다.
- 별도 Entry date and time UI 통과. 전체 Workspace usability 17개 통과, 기존부터 남아 있던 달력 제스처 검사 4개 실패는 동일합니다(continuous-workspace 1개, jade-paging 3개). 이번 수정으로 추가된 실패는 없습니다.
- 배포 대상: https://myiharu.com/tuition, PR #67.
