# UI 7.3 — 가족이 직접 시작하는 연결

## 사용자 흐름과 책임

| 사용자 | 시작 방법 | 승인하는 대상 |
| --- | --- | --- |
| 가족을 만든 성인 보호자 | 자신의 계정으로 로그인 → 가족 이름 등록 | 가족 코드로 들어온 다른 보호자의 참여 요청 |
| 자녀를 등록한 보호자 | 자녀 별명 입력 + 정보 처리 동의 | 해당 자녀의 기기 연결·정보 공유 범위 |
| 아이 | 로그인 화면의 아이 연결 → 6자리 번호 발급 | 보호자가 선택한 자기 이름을 확인하고 기기 연결 마침 |
| 초대받은 보호자 | 자신의 계정으로 로그인 → 받은 가족 코드 입력 | 요청 후 가족 관리자의 수락을 기다림 |

새 프로필은 보호자가 직접 등록한 SELF_DECLARED 프로필이다. 법정 가족관계를 기관이 인증했다고 표시하지 않는다. 자녀 이메일·비밀번호·생년월일은 수집하지 않는다. 기존 기관 관계 심사와 검증 결과는 변경하지 않으며, 기존 경로는 legacy 하위로 분리한다. 예전 심사 페이지 북마크는 시작 가이드로 이동한다. 보호자 계정 인증, 최근 본인 확인, 가족 멤버십, 아이별 공유 권한은 유지한다.

## 기능

- 첫 로그인 홈에 시각적 3단계 가이드. `/start`와 `/family`에서 이어서 진행.
- 새 가족 생성은 운영자 심사 없이 성인 보호자가 책임을 확인하고 직접 수행.
- 자녀 별명만 입력. 일반 정보 처리 동의를 별도로 기록. 위치 동의는 기본 꺼짐.
- 가족 코드는 IH-XXXX-XXXX-XXXX 형태의 60비트 임의 코드 (혼동하기 쉬운 I/O/0/1 제외). 서버에는 HMAC만 저장. 입력은 사용자당 10분 5회·IP당 30회로 제한. 24시간 만료·재발급 시 이전 미사용 코드 폐기. 코드를 입력해도 참여는 PENDING이며 관리자가 수락해야 함.
- 참여 수락만으로 자녀 데이터가 공유되지 않음. 기존 아이별 권한 설정 사용.
- 아이 기기는 기존 일회성 6자리 번호·보호자 승인·아이 확인·HttpOnly 기기 세션 사용. 다른 기기에서 시작해야 함. 인증 토큰을 localStorage에 저장하지 않음.
- 신규 프로필은 등록한 보호자가 최근 본인 확인 후 삭제 가능. 자녀 소유 일정·대화·기기·개인정보 레코드 FK 계통을 원자적으로 삭제하며 다른 가족·아이 레코드는 유지.

## 디자인·메뉴 전수 점검

달력·반복 일정이 오래된 독립 레이아웃을 사용해 사이드 메뉴가 숨겨지던 원인을 제거했다. 공통 AuthLayout, 브랜드, 오른쪽 메뉴, 화면 설정과 본문 스크롤로 전환한다. 계정의 보조 화면에서도 공통 메뉴를 유지한다. 아이 메뉴의 내 하루 경로는 `/child/connected`, 일정은 `/child/schedules`로 수정한다.

오늘·달력·반복 일정은 같은 WorkspaceTabs를 사용한다. 가족·시작 가이드·계정도 같은 탭 컴포넌트를 사용한다. 탭의 높이·배경·선택색·모서리를 통일한다. 모바일은 하단 메뉴가 별도 행을 차지하여 본문을 가리지 않는다.

## 검증 범위

- 신규 API: 동의 누락 거절, 무권한 가족/자녀 접근 거절, 코드 요청·수락, 참여 후에도 자녀 정보 비공개, 생년월일 미수집.
- 실제 PostgreSQL: 비소유 app_runtime 역할에서 등록, 일정·대화 생성 후 프로필 삭제, 관련 데이터 삭제와 다른 자녀 보존.
- 브라우저: 실제 가입·로그인 → 가이드 → 가족 생성 → 자녀 추가 → 보호자 참여 승인 → 이메일 없는 아이 기기 연결.
- 운영 메뉴 15곳 × 320/390/768/1024/1440px: 브랜드·메뉴 유지, 바깥 스크롤 없음.
- 기존 기관 검증·동의·공유·일정·등하원·대화·테스트 작업실 회귀 유지.

## 운영 반영 순서

검증 통과한 SQL을 먼저 반영하고 적용 파일명·체크섬을 기존 원장에 기록한다. 이어 동일 커밋을 배포한다. 기존 API는 새 함수가 없어도 동작하므로 사전 SQL 반영은 기존 앱과 호환된다. 실제 이용자의 가족이나 자녀를 배포 과정에서 만들거나 삭제하지 않는다.
