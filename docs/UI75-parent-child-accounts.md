# UI75 — 보호자·자녀 로그인과 번호 승인

2026-11-07, 운영 기준 UI74 / 5a6e51c.

## 사용 흐름

| 역할 | 회원가입·로그인 | 가족 연결 |
| --- | --- | --- |
| 보호자 | 기존 이메일 계정 또는 기존 Google·카카오·네이버 플랫폼 로그인. 회원가입은 별도 화면 | 로그인 후 가족 관리에서 자녀의 6자리 번호 입력 → 이름·자녀 아이디 확인 → 보호자 동의 후 승인 |
| 자녀 | 이름·비밀번호로 가입. 이메일 불필요. 동명이인 구분용 자녀 아이디를 서버가 자동 발급 | 가입 화면에 15분짜리 번호 표시 → 보호자 승인 후 인증 완료 → 내 하루 시작 |
| 재로그인 | 자녀 아이디·비밀번호 입력 | 이미 승인된 가족으로 로그인. 승인을 다시 받을 필요 없음 |

- 승인은 로그인한 보호자가 직접 수행하며, 외부 심사기관의 법정대리인 신원 검증으로 표시하지 않는다.
- 보호자가 가족을 만들지 않았어도 첫 자녀 승인 때 자동 생성한다. 기존 운영 가족을 선택할 수도 있다.
- 자녀 이름만으로 계정을 찾지 않는다. 서로 다른 자녀가 같은 이름을 사용할 수 있다.
- 보호자와 자녀가 같은 브라우저에서 계정 역할을 섞지 않도록 안내한다.
- 기존 번호 기기 연결·공유 관리 기능은 호환 경로 `?legacy=1`로 유지한다. 기본 `/device/connect`는 새 자녀 로그인으로 안내한다.

## 접근 제어·저장

- 자녀 비밀번호: 랜덤 salt + Node scrypt 해시. 평문 저장·로그·응답 없음.
- 자녀 인증 정보: 비공개 스키마, RLS 강제, 브라우저 역할 및 app_runtime의 테이블 직접 접근 금지.
- 번호·가입 증명·기기 토큰은 HMAC 해시로 저장한다. 번호는 15분, 가입 대기는 24시간이며 재발급 시 이전 번호 무효화.
- 가입 증명·기기 세션은 HttpOnly·SameSite=Strict 쿠키, 운영 HTTPS에서 Secure 및 __Host 접두어.
- 보호자 승인: 유효한 HIGH 로그인 세션과 확인된 보호자 이메일, 현재 자녀 요청 ID, 본인 소유 가족, 명시적인 보호자 동의를 서버와 DB에서 검사한다.
- 일반 정보 동의만 생성한다. 위치 공유는 자동으로 허용하지 않는다.
- 승인 경쟁은 행 잠금으로 직렬화하고 한 보호자에게 한 번만 연결한다. 첫 기기 발급 응답 손실 재시도는 같은 세션을 반환한다.
- 자녀 기기 2대 제한, 가족당 자녀 5명 제한 및 요청 횟수 제한 유지.
- 새 DB 변경은 비공개 테이블 2개·제한된 정책 함수 1개와 생년월일 선택 항목 전환이다. 기존 생년월일 값은 바꾸지 않고 가짜 값을 생성하지 않는다. 데이터 삭제 기능이나 FK 삭제 전파는 추가하지 않는다.

## 화면 수정

- 로그인 대상은 보호자·자녀 탭으로 구분하고 회원가입 링크는 별도 제공한다.
- 보호자/자녀 로그인·가입 카드의 중앙 정렬, 입력칸·비밀번호 표시 버튼·주 행동 버튼 간격 통일.
- 가족 초대의 입력칸과 확인 버튼을 같은 폭의 세로 폼으로 정리.
- 작은 화면과 큰 글씨에서는 장식 영역을 줄이고 입력·행동 버튼에 집중한다. 내부 스크롤로 하단 행동을 가리지 않는다.

## 검증

API 단위: 승인 전 세션 차단, 익명 보호자 승인 차단, 정확한 자녀 요청 확인, 다른 부모의 번호 재사용 차단, 가족 간 격리, 재로그인·비밀번호 오류, 번호 갱신·만료, 쿠키, 위치 기본 비공유, 테이블 직접 접근 차단.

실제 PostgreSQL: 동시 보호자 승인 한 번 성공, 첫 기기 발급 응답 재시도의 동일성 및 테이블 권한.

브라우저: 자녀 가입 → 보호자 승인 → 자동 가족 연결 → 자녀 시작 → 다른 브라우저에서 비밀번호 로그인. 320/390/768/1440px에서 로그인·가입·초대 폼 폭과 버튼 위치 검증. 기존 전체 메뉴·반응형 회귀도 함께 실행.
