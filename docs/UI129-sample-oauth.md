# UI129 — 소셜 로그인 복구 및 비회원 샘플 화면

기준: UI128 `a1dda78f7e3c0989245c77cb8ba9c4e43559d7a4` / 2026-11-10 KST

## 변경 동작

- 비회원 시간표 위의 큰 iHaru 로고·로그인 상단바와 안내 문구 행을 제거했다. 최초 시작 로고 애니메이션은 유지한다.
- 시간표, 달력, 학원비, 대화, 메모, 가족 관리에 가상 예시를 표시한다. 시간표·달력·학원비의 기존 구성원 필터 옆에 `샘플 데이터`를 표시한다. 날짜·월·보기·구성원 변경은 로그인 없이 탐색할 수 있다. 좁은 시간표에서는 첫 자녀를 기본 선택하며 다른 샘플 자녀도 선택할 수 있다.
- 등록, 샘플 일정 누르기, 메시지 보내기, 가족 연결은 기존 로그인 시트를 연다. 로그인 이후에는 해당 계정의 자료를 조회한다. 계정·개인정보·알림 설정·관리자·가족 초대 페이지의 인증 및 권한 제한은 유지한다.
- 샘플은 브라우저 메모리에서만 생성한다. 계정·DB·대화 API·실시간 구독에 연결하지 않는다. 로그인 후 재개할 때는 종류·날짜·시간만 전달하며 제목·이름·금액·본문은 복사하지 않는다. 실제 저장은 사용자가 직접 저장할 때만 한다.

## 로그인 실패 원인과 수정

운영에서 `/api/auth/sign-in/social`에 현재 클라이언트와 같은 `{provider:"google", callbackURL:"/timetable", errorCallbackURL:"/login?next=%2Ftimetable"}`를 보내면 HTTP 400 `INVALID_CALLBACK`이 반환되었다. UI128에서 복귀 주소를 변경한 후 서버의 고정 허용 목록을 갱신하지 못한 것이 원인이다. 달력 등 복귀 경로와 이메일 인증의 `next`도 같은 문제가 있었다.

소셜 시작과 이메일 인증 GET/POST에 공통 검증 정책을 적용했다. 앱 내부의 명시된 경로와 필요한 `next`만 허용한다. 외부 도메인, 프로토콜 상대 URL, 중복 쿼리, 제어문자, 임의 복귀 경로는 거절한다. 계정 연결과 암호 재설정의 복귀 화면은 계속 고정한다. Origin, state, PKCE, 서명 검증, HttpOnly 쿠키, 명시적 계정 연결 정책은 유지한다. 설정값·OAuth 비밀·DB 마이그레이션 변경은 없다.

## 검증

- 전체 단위·통합 검사 257개, `npm run build`, `npm run typecheck` 통과.
- 실제 Better Auth·격리 PostgreSQL 인증 검사와 복귀 경로 검사 40개 통과: 실제 클라이언트 요청, Google RS256 서명/JWK 콜백, 계정 세션, 달력 복귀, state 재사용 거절, 이메일 인증 복귀, 외부 주소 차단 포함.
- 이전 브라우저 검사는 앱의 소셜 로그인 응답을 가짜 응답으로 대체해 이 오류를 놓쳤다. 이제 앱의 실제 로그인 API와 제공자 설정을 통과하고 외부 Google 페이지에 도달하는지 검사한다. 외부 페이지 표시만 격리 대체하며, 서명된 제공자 콜백은 위의 실제 서버 검사에서 별도로 검증한다.
- 브라우저 회귀 검사 11개 통과: 샘플 탐색, 상단바 제거, 입력 시 로그인, 로그인 후 빈 새 입력·계정 자료 전환, 샘플 미저장, 뒤로 가기, 자녀 권한, 모바일/데스크톱·다크·모션 감소. [전용 CI](https://github.com/123456789pjh321-beep/iharu/actions/runs/42712767361)는 실제 인증 검사 및 복귀 위치 검사 44개도 통과했다. 최초 UI129 검증 소스는 `b3b76c6605078724a0a631351bee9a435d760c69`이다. 아래 F01에서는 운영 확인 중 발견한 외부 인증 취소 복귀를 추가 보완한다.
- 기존 달력·알림, 읽기·스와이프, 공지·문서 저장, 시작 로고, 날짜·시간 입력 회귀와 실제 PostgreSQL 동시성·역할 분리 단계도 통과했다. 전체 E2E에는 이전부터 알려진 실패가 있으므로 전용/관련 회귀 결과를 전체 CI 통과로 표현하지 않는다.
- 운영에서는 OAuth 시작 응답과 실제 화면을 확인한다. 개인 Google 계정의 자격 증명 입력 및 최종 동의는 자동 수행하지 않는다.

## UI129-F01 — 외부 인증 취소 후 복귀

운영에서 Google 계정 선택 화면까지 정상 이동함을 확인했다. 다만 그 화면에서 브라우저의 뒤로 가기를 사용하면 bfcache에 보존된 `busy=true`가 복원되어 로그인·닫기 버튼이 계속 비활성화되었다. `pageshow.persisted`일 때 진행 중이던 소셜 이동만 해제해 같은 화면에서 재시도하거나 닫을 수 있게 했다. 일반 이메일 요청의 중복 제출 제한에는 관여하지 않는다. 격리된 브라우저에서 bfcache를 실제로 활성화하고 캐시 복원 여부, 버튼 복구, 원래 달력 월, 취소 시 임시 입력 위치 제거를 추가 검증했다.


F01 결과: [전용 CI](https://github.com/123456789pjh321-beep/iharu/actions/runs/42716643007)에서 인증·복귀 경로 44개와 브라우저 12개가 모두 통과했다. 실제 `pageshow.persisted=true` 복원, 재시도 및 닫기 버튼 활성, 원래 달력 월 유지, 취소 시 임시 위치 제거를 포함한다. F01 검증 소스는 `82160f3ec71163bd7590977160e82c7977ed8193`이며 이후 변경은 결과 문서뿐이다. 캐시 재현 대역은 테스트 전용 TLS 출처이며 운영 인증 API와 보안 설정을 변경하지 않는다.
