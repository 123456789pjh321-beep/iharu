# UI139 — AI 브리핑

## 사용자 흐름

하단 메뉴는 **시간표 → 달력 → 대화 → AI 브리핑 → 가계부 → 더보기** 순서입니다. AI 브리핑은 로그인한 성인의 개인 피드이며, 어린이 메뉴에는 표시하지 않습니다. 비로그인 접근은 해당 화면의 로그인 창으로 연결합니다.

AI 브리핑의 `내 브리핑 시작하기` 또는 `브리핑 설정`에서 사용 여부, 기준 지역, 외부 분석 동의를 저장합니다. 처음 켠 사용자는 다음 한국 시간 새벽 3시부터 처리합니다. 위치 권한만으로 분석 동의를 대신하지 않습니다. `현재 위치로 지역 추천`은 기기에서 좌표를 가까운 도시 이름으로 변환하고, 사용자가 확인해 저장한 시·구 문자열만 서버에 전달합니다. 정확한 좌표나 위치 이력을 서버에 추가 저장하지 않습니다.

사진, 짧은 요약, 최대 3개 주제 이동, 원문 링크, 자세한 이유·챙겨볼 일·확인한 원문, 보관함, 도움 됨, 숨기기를 제공합니다. 사진은 서버에 포함한 Unsplash 주제 사진이며 실제 공지 현장의 사진으로 표현하지 않습니다. 카드에 `주제 사진`과 사진 출처를 표시합니다. 상세 저작자는 `web/public/briefing/ATTRIBUTION.txt`에 있습니다.

## 배치와 게시 정책

| 항목 | 구현 동작 |
| --- | --- |
| 시작 시각 | 한국 시간 매일 03:00, Vercel UTC `0 18 * * *` |
| 후속 처리 | 기존 분 단위 크론에서 검색·분석 작업을 차례로 처리하고 장애 후 같은 날짜 작업을 재개 |
| 범위 | 오늘부터 7일간 실제 발생하는 시간표·달력, 신규·수정 항목 우선, 관련 시설·장소 최대 12곳 |
| 허용 일정 | 내가 등록한 일정, 내가 연결을 승인하고 현재 읽을 권한이 있는 어린이의 일정 |
| 우선 정보 | 시설 휴관·이용 변경, 중요한 공식 공지, 이벤트 |
| 후속 확장 | 지역 행사·교육 프로그램·지원 소식은 지역별 공식 공급처를 늘리는 방식으로 확장 가능 |
| 공식 출처 | HTTPS `.go.kr`, `library.kr`, `airkorea.or.kr` 원문. 검색이 실제 반환한 출처만 사용 |
| 게시 검증 | 원문 직접 확인, 시설·지역 일치, 일정과 유효 기간 교차, 원문의 실제 인용·날짜 확인, 종합 점수 80 이상 |

| 중복 | 같은 사건 식별값 또는 같은 공지 URL·시설·분류면 기존 글 갱신, 같은 내용은 재게시하지 않음 |
| 소식 없음 | 새 글 없이 마지막 확인 시각 갱신. 연결·원문 확인 실패는 소식 없음과 구별 |
| 동의 철회 | 개인 피드와 대기 작업 삭제, 이미 실행 중인 결과도 게시할 수 없도록 무효화 |

고정된 일반 게시 시각을 보장하는 알람 서비스가 아닙니다. 03:00부터 대기열을 처리하므로 계정 수와 공급처 응답에 따라 게시 시각은 늦어질 수 있습니다. 새로고침은 저장된 피드만 읽으며 OpenAI 호출을 추가하지 않습니다. 긴급 예외도 해당 배치에서 확인한 소식에 한정되며 실시간 안전 경보 서비스를 대신하지 않습니다.

## 서버·데이터 설계

- 서버 전용 `/api/cron/briefing`과 기존 크론은 같은 `CRON_SECRET` 검증을 사용합니다. 브라우저가 분석·게시 작업을 직접 실행할 수 없습니다.
- 검색과 구조화 분석을 분리합니다. 서버에서 암호화된 기존 OpenAI 키를 필요한 작업 중에만 복호화하고, Responses API에 `store:false`로 요청합니다. 기본 모델은 공식 문서의 웹 검색·구조화 출력 지원을 확인한 `gpt-5.6-luna`입니다.
- 검색에는 지역·날짜·공개 시설명만 전달합니다. 분석에도 메모·금액·정확한 좌표·개인 식별자를 전달하지 않습니다. 이름, 이메일, 전화번호, 상세 주소, 민감한 자유 문구를 줄이고 공개 장소가 확인되지 않는 일정은 건너뜁니다.
- 원문 수집은 공식 도메인만 허용하고 공개 IPv4 DNS를 검증·고정합니다. 사설 주소, 비공식 리다이렉트, HTML 이외 문서, 과도한 본문·응답 시간을 차단합니다. 외부 원문은 명령으로 실행하지 않습니다.
- 개인 피드·설정·반응·작업·사용량 6개 테이블은 강제 RLS를 사용합니다. 앱 역할은 개인 명령 함수만, 작업 역할은 작업 명령 함수만 호출할 수 있으며 테이블과 내부 보조 함수는 직접 접근하지 못합니다.
- 2분 작업 임대, 단계별 최대 2회 시도, 토큰별 호출 예약, 계정·날짜 고유 작업으로 중복 게시와 무제한 재시도를 막습니다. 완료 시 동의·계정 상태·연결 권한·일정 범위·운영 설정·키 버전을 다시 확인합니다.
- 최고관리자는 기존 `시스템관리 → AI 설정`에서 전체 사용 여부와 전체 서비스의 하루 호출 예약 한도를 변경할 수 있습니다. 기본 100회, 설정 범위 2~1000회입니다. 검색·분석 각각 1회이며 검색 도구는 요청당 최대 3회입니다. 이는 금액 한도가 아니며 재시도도 예약 횟수에 포함됩니다. 관리자 변경은 최근 재인증과 감사 기록을 적용합니다.
- 일반 작업은 2일, 피드와 사용량은 90일 보관 기준을 적용합니다. 연결이 끊긴 어린이의 자료에서 나온 기존 글은 다시 표시하지 않습니다. 게시 원문의 유효 기간이 끝난 주제도 표시하지 않습니다.

## 운영 반영

1. 기존 UI138 상태에 `db/migrations/20261110073501_ai_briefing_feed.sql`을 한 번 적용합니다. Supabase 미러 SQL은 동일한 내용입니다. 이미 적용한 마이그레이션을 수정하거나 다시 실행하지 않습니다.
2. 기존 `AI_CREDENTIAL_ENCRYPTION_KEY`, 등록 OpenAI 키, `CRON_SECRET`, 작업 DB 연결을 그대로 사용합니다. 암호화 마스터 키를 교체하지 않습니다. 공급자 키나 비밀값을 ZIP에 포함하지 않습니다.
3. 사용자 설정은 기본 꺼짐입니다. 최고관리자가 대신 동의하거나 운영 DB에 예시 게시글을 넣지 않습니다. 각 사용자가 지역·동의를 저장해야 다음 03:00 배치에 포함됩니다.
4. 운영 중지는 시스템관리의 전체 사용 여부로 처리합니다. 프런트엔드 롤백 시에도 추가된 테이블은 보존할 수 있습니다. 데이터 삭제를 동반하는 역마이그레이션은 제공하지 않습니다.

## 검증

관련 로컬 검사 32개와 빌드가 통과했습니다. 전체 단위/API 검사 **321개**, 실제 PostgreSQL 17 검사 **44개**, 브리핑·관리자 화면 우선 검사 **7개**가 CI에서 통과했습니다. 320/820/1440px 사진 카드의 렌더링과 모바일 메뉴를 확인했습니다. 기존 메뉴를 포함한 통합 화면 검사 **48개**, 대화·비로그인·스티커 검사 **16개**도 통과했습니다. 운영 반영 결과는 PR #71의 최종 설명을 참고합니다. 테스트의 공급자 응답과 게시글은 격리된 가짜 자료이며 운영 키로 실제 유료 분석을 실행하지 않습니다.

검증 소스: `bf18ec0071de0bdcc00d191f05ff6506d09e7c7e` (PR #71).

기존 전체 검사에는 이번 작업과 분리된 실패가 있습니다. Workspace usability의 달력 드래그·월 이동 4개 실패는 UI138에서 이미 확인된 동일 항목이며 해당 달력 소스는 변경하지 않았습니다. Android API 36 에뮬레이터의 native offline 화면 검사도 실패했습니다. 네이티브 코드·빌드 입력은 변경하지 않았고, Android 빌드 재사용·API 28 실행 검사는 통과했습니다. 따라서 전체 CI가 모두 통과했다고 표현하지 않습니다.
