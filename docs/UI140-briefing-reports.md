# UI140 — AI 브리핑 정보 신고 및 철회

BR04에서 사용자 신고와 최고관리자 검토 흐름을 먼저 추가합니다. UI139에 추가된 개인 브리핑을 기준으로 합니다.

## 사용 방법

1. AI 브리핑 카드에서 해당 주제를 선택하고 **소식 메뉴 → 잘못된 정보 신고**를 엽니다.
2. 신고 사유를 고르면 해당 주제의 제목, 요약, 적용 기간과 출처가 검토 목록으로 전달됩니다. 관리자 화면에는 신고자 정보와 개인 일정 연결 사유가 표시되지 않습니다.
3. 최고관리자는 **시스템관리 → AI 브리핑 설정 → 브리핑 신고 검토**에서 원문을 열고 **게시 유지** 또는 **주제 철회**를 선택합니다. 이전 본인 확인이 만료됐으면 다시 확인한 뒤 처리합니다.
4. 철회하면 같은 원문 URL, 주제 식별값과 근거 버전을 가진 항목이 브리핑과 보관함에서 사라집니다. 카드에 다른 주제가 있으면 계속 볼 수 있습니다. 같은 근거 버전은 유효 기간 내 자동 게시에서도 제외되며, 근거가 갱신된 주제는 기존 검증을 거쳐 게시될 수 있습니다.

최고관리자 화면은 미처리 신고를 접수순으로 최대 20건 표시합니다. 신고를 처리하면 목록이 갱신됩니다. 같은 카드에서 같은 근거 버전을 반복 신고하면 기존 접수로 처리합니다. 신고 데이터는 원래 카드와 함께 삭제되며, 처리 이력은 시스템관리 감사 로그에 남습니다.

## 반영 순서

운영에 반영할 때 UI139 이후 마이그레이션 `20261111043409_ai_briefing_reports.sql`을 먼저 적용하고 앱을 배포합니다. `db/migrations`와 `supabase/migrations`의 동명 SQL은 동일한 마이그레이션입니다. 기존에 사용하는 마이그레이션 경로를 이용합니다.

## 검증

- 전체 단위·API 검사 322개와 프로덕션 빌드 통과
- PostgreSQL 17 통합 검사 45개 통과. 동시 신고 중복, 역할 격리, 철회와 게시 작업이 겹치는 경우 포함
- Chromium 브리핑·관리자 검사 8개 통과. 320px 화면에서 신고를 접수하고 관리자 철회 뒤 같은 카드의 다른 주제가 유지되는 흐름 확인
